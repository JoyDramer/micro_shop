# Работа с проектом

## Контекст

Это действующий интернет-магазин на облачном сервере Timeweb.
Актуальные исходники находятся в /root/shop_project/micro_shop.
Локальные старые копии не являются источником актуального кода.

В проекте есть frontend, api_gateway и отдельные сервисы.
Конфигурация контейнеров находится в docker-compose.yml.
Точные связи сервисов и команды проверять по исходникам.

## Перед изменениями

- Прочитать применимые вложенные AGENTS.md.
- Проверить git status и изучить изменения в затрагиваемых файлах.
- Сохранять существующие изменения пользователя.
- Определить, как изменение повлияет на работающий сайт.
- Проверить настройки volumes и автоматической перезагрузки:
  сохранение исходника может немедленно изменить работающий сайт.

## Изменение кода

- Делать минимальные изменения в рамках задачи.
- Не проводить попутный рефакторинг и обновление зависимостей.
- Не менять публичные API без проверки вызывающего кода.
- Не изменять секреты и параметры окружения без явной задачи.
- Новые правила и команды описывать только после их проверки.

## Проверки

- Находить команды проверки в package.json, конфигурации тестов
  и документации проекта.
- Выполнять проверки, соответствующие изменению.
- Не запускать тесты, которые могут обращаться к рабочей базе,
  отправлять сообщения или создавать реальные платежи.
- Если безопасная проверка недоступна, сообщить об этом явно.
- По завершении описать изменения, проверки и оставшиеся ограничения.

## Работающий сервер

Без явного указания пользователя не выполнять:
- публикацию изменений и пересборку работающих контейнеров;
- остановку или перезапуск сервисов;
- миграции и изменение данных рабочей базы;
- удаление файлов, Docker volumes и очистку Docker;
- изменение SSH, firewall, прав доступа и системных настроек.

Перед согласованным изменением данных или инфраструктуры
проверить наличие подходящей резервной копии и способ отката.

## Git и секреты

- Не добавлять в Git пароли, токены, приватные ключи и .env.
- Не добавлять зависимости, кеши, логи, дампы и резервные копии.
- Не отменять чужие изменения и не переписывать историю.
- Не выполнять git reset --hard, git clean или force push
  без явного указания пользователя.
- Перед коммитом проверять staged diff на секреты и лишние файлы.
- Коммиты и отправку в remote выполнять по запросу пользователя.
